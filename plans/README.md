## Findings considered and rejected

- **Hardcoded `com.rogueamoeba` / `com.bearisdriving.BGM` filters**
  (`AppResolver.swift:42-43`): kept for now; they prevent feedback loops with
  SoundSource/Background Music on the development machine. Revisit before a
  public release, where a role-based filter is preferable.
- **Rows persist after playback stops** (`AudioEngine.hasTaps`): intentional;
  keeps per-app controls reachable. Plan 005 documents it instead of removing it.
- **`LevelStore` writes on every slider tick** (`Models.swift:39-44`):
  `UserDefaults` coalesces; not worth a debounce at this scale.
- **No CI, lint, formatter or pre-commit hooks**: a single-developer local app
  at audit time. Add when the project grows; not a plan now.
- **Tap start remains synchronous on the main actor** (`AudioEngine.swift:6,191-195`):
  deferred. Plan 002 gives the lifecycle a seam; moving creation off-main becomes
  a local change if UI hitching is observed.
- **Output-device change is a hard stop with no crossfade**
  (`AudioEngine.swift:128-131,250-255`): deferred to the routing/device work.
  Plan 002 keeps the rebuild behavior but centralizes it; a gap/click is accepted
  in v0.1.
- **Daemon-only audio is hidden** (`AppResolver.swift:81-84`): intentional v0.1
  policy; revisit with a "show system audio" toggle.
- **No app icon, notarization or Developer ID release**: product polish, not an
  architecture/bug plan.
- **Git initialized after the audit**: the plans' SHA-256 baseline is the
  initial commit; future plans can use commits.

## Not audited

- Real USB / Bluetooth / multichannel hardware, sample-rate switching, and
  hotplug timing.
- VoiceOver interaction beyond static accessibility labels.
- Long-running CPU/memory after hours of playback.
- TCC denial/regrant edge cases beyond the observed prompt.
- No static analyzer was available (no SwiftLint/SwiftFormat installed).
